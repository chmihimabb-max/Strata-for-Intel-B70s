D2x (t_85e61269): the bench that prices an XMX MMVQ on the decode path's own shapes

bench/micro/mmvq_xmx_price.cpp + its CMake target.  A measurement, not a rewrite: no engine source, no
config, nothing in this card's tree is read by the engine.

What it measures, in the order the questions have to be asked:

  1. the device's joint_matrix shapes, RE-RUN at HEAD rather than inherited from probe21's header table
     (include/strata/sycl_compat/sycl_xmx.hpp:7-24).  The result is not the recorded one: the int8
     8x32x16 / 16x32x16 dot is refused by the driver (the same text probe21 recorded), and the f16/bf16
     16x16x16 tiles probe21 recorded as RUNNING no longer build at all on this toolchain - the backend has
     no implementation for the PackedA load the compiler emits for them.  f16/bf16 8x16x16 RUNS, and that is
     the only tile left for a GEMV-shaped kernel on this card.
  2. the card's streaming read rate, with the trap named: a memset-filled 1 GiB buffer reads at 1352 GB/s,
     the same buffer hash-filled (incompressible) at 571.6 GB/s - this driver compresses uniform pages, so
     a constant-filled buffer is not a bandwidth measurement.  Quantized weights are incompressible, so the
     floors use 571.6 GB/s.
  3. the shipped dispatch (native_mmvq, default layout) and llama.cpp's generic multi-column layout, at
     all 25 distinct (type, n_in, n_out) geometries the pack's 301 dense matrices use (d2/D2-TYPES.txt,
     cross-checked against the pack's GGUF), at ncols 4 and 6, priced in-stream (reps launches back to
     back / reps - what the engine's own census measures) with the one-call sync'd price beside it.
  4. an f16 8x16x16 XMX MMVQ prototype of the same dot product, on REAL dequantized weights (the tree's own
     host dequantizers, include/strata/artifact/dequant.hpp), repacked into 8x16 tiles the way a real
     implementation would at load time, with the repack timed per case.
  5. its accuracy against an fp64 dot of the same dequantized weights on the same activations, over three
     separated row windows, separating the f16 encoding's error from the kernel's own arithmetic.
  6. the window extrapolation: every variant x the census's own launch counts, against the census's
     51 267.3 us.

The proxy check: the shipped-layout column extrapolates to 52 418.4 us against the census's 51 267.3 us
(+2.2%; +1.2% in an identical re-run), and per type to 0.86-1.14x of the census's own per-type microseconds
- so the rig is the window's dense family, priced 301 times.

The CMake target is registered for SYCL as well as CUDA on purpose: the two existing mmvq harnesses sit
inside an `if(NOT STRATA_ENABLE_SYCL)` block and are therefore absent from this tree's build.  With SYCL off
and CUDA on it would be duplicated, hence the separate guarded block (a CUDA build only takes the CUDA one).
