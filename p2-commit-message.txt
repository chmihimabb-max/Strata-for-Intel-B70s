P2 (t_a1b6fa6c): the QSA prompt attention's hi/lo mma pair rebuilds its B fragment once

`mma16816(c, ah, b); mma16816(c, al, b);` is how all four mma sites of the prompt attention use the
m16n8k16 emulation: the SAME B fragment in both calls, and include/strata/sycl_compat/mma16816.hpp
rebuilds it - 16 select_from_group gathers and 32 f16->f32 conversions of the 16 B values - once per
call.  `mma16816_f32_pair` builds it once for the pair, and the two halves' 16-term k loops are
interleaved (each of the eight accumulators still takes its own products in its own k order, and the hi
half still reaches c before the lo half), so the arithmetic is unchanged: same products, same order,
same rounding.

Measured, BMG-G31, one card, bench/micro/p2_qsa_emul_cost.cpp (4000 iterations over 8192 work-items):
  two calls   5.848 ms      the fused pair 4.725 ms = 19.2% cheaper
  128 FMA only 0.751 ms     (the emulation is 7.79x the arithmetic it replaces, 6.29x after this)
  64 select_from_group alone 1.616 ms, 128 f16->f32 alone 0.683 ms
The kernel's own parity program (sycl_prompt_attn_parity, ctx 32768, 2048 queries): all four cases PASS
with the same error figures as before the change (int8 err_new 2.14e-06, new-vs-old 4.53e-06), and the
kernel is 511.5 -> 503.4 ms per chunk (1.6%) - i.e. the emulation's redundancy is NOT this kernel's
bottleneck, which the micro says too: its FMA content is 4-9% of the card's FP32 rate.

src/kernels/cuda/qsa_prompt_attn.cu is untouched: the fusion is expressed as hand-port replacements
(tools/sycl/handport/qsa_prompt_attn.py, entries #6) over the four paired call sites, and
src/kernels/sycl/qsa_prompt_attn.cpp is regenerated by tools/sycl/handport.py qsa_prompt_attn.
